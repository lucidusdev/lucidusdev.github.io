Posted on 2026-06-02 Edited on 2026-06-04

Native binary

Chromecast drops connection

I have a Chromecast speaker(a Lenovo clock actually). Ran into another problem that the speaker quietly stopped playing after 20-30 minutes. This seems to be a common issue and was reported. The fix, as suggested, is to use airconnect and set the speaker as an Airplay device, and no more interrupted streaming!

Keep airconnect connected

airconnect may drop the speaker after long time idle. Restarting airconnect fixes it.

A quick hack to check & restart airconnect if it's not running(0% CPU Usage):

  • Create an airconnect service file /etc/init.d/airconnect

  • enable the service.

  • Check airconnect CPU usage and restart if it's 0.0.
    This requires full top from procps-ng-top package.

    put it in crontab and run hourly.

Home Assistant "Integration"

Originally set music assistant server but seems overly complicated for my small music collection. HA(docker image in same OpenWrt router) has Owntone integration and can detect the server.

Owntone can be controlled with builtin music card in HA but it's very limited, can't even view the playlist. I later settled with Owntone's own web UI on "webpage" card and embedded the player url(http://192.168.1.100:3689/#/player) on HA dashboard.
