OMM.py: Logitech Onboard Memory Manager in python and beyond

Posted on 2025-07-25

Never a fan of G-Hub, LGS is OK but also limited and incompatible with newer models. Logitech's OMM(onboard memory manager) is nice but buggy, with very limited feature support, so I decided to make my own.

Logitech devices use their own protocol "HID++", older ones are 1.0, newer(even my G502 core from 2015) units are on 2.0 and the HID++ 2.0 is easy to work with -- other than very limited document and have to rely on various Linux projects to find the necessary functions and parameters.

Logitech has a specified feature for managing onboard profile, and by calling it with various parameters, one can get device capacities and change the profile options. And it can also be used to switch between "host"(controlled by G-Hub) and "onboard" mode, simple and could completely eliminate the initial installation of bloatware -- but missing in OMM.

And, now for the actual button remap. This can be an issue for official software. Other than limited features, I've also seen several users struggled binding "alt+tab" or "alt+f4", or a simple "shift" or "ctrl" key...the hardware has everything ready but factory software is more on ease of use than properly implementing features -- how about let user select key combinations instead of capturing from keyboard?

Another missing piece is macro -- it's gone in OMM, and heavily restricted in official software -- even in old good LGS. On Linux side, the popular Solaar and libratbag have basic or no macro support. It's well supported in libhidpp project and my omm.py is based on it.

Other than basic keystrokes(key down, key up), the hardware macro is quite powerful, and can do things like:

  • move mouse, click buttons and 4-way wheel scroll

  • flow controls, a comparison

    Macro Type G-Hub software onboard mode(omm.py)
    no repeat: run once support support
    repeat while holding support support
    toggle support no support. only endless loop but anyone want it?
    sequence mouse down -> action 1 -> holding -> action2(loop) -> mouse up -> action 3 limited support without holding loop.
    mouse down -> action 1 -> holding -> nothing -> mouse up -> action 2

Finally the RGB light, I don't use it often but that's another annoyance as OMM will only set both zones(in my G502 that's DPI and Logo) to same effects. It's always better to have some different options.

The project is on my github repo. It's (developed/tested on) Windows only but hopefully to get macOS and Linux support with the magic of hidapi.
